## 続きの手順

残りのステップ（13-48）についても同様の手順で微細分割を行うことができます。各ステップについて：

### 微細分割の基本フロー
1. **元のステップの目的を理解する**
   - IMPLEMENTATION_PLAN_CODE_REVIEW_48_STEPS.md から対象ステップを確認
   - 「目的」セクションを読んで、何を達成したいかを理解する

2. **作業内容を具体的なアクションに分解する**
   - 「作業内容」を読んで、何をするべきかを理解する
   - それぞれの作業を「ファイルを開く」「行を検索する」「文字列を置換する」「ファイルに書き込む」などの具体的なアクションに分解する

3. **各アクションが3-5分で完了可能なレベルまで細分する**
   - 1つのアクションが5分以上かかるようなら、さらに細分する
   - 例: 「ファイルを変更する」→「ファイルを開く」「変更箇所を探す」「変更する内容を準備する」「置換を実行する」「変更を確認する」

4. **確認ポイントと期待される出力を明確にする**
   - 各マイクロステップ後に「確認」項目を設ける
   - 確認方法（ツールの使用、ファイルの内容チェックなど）を具体的に指定
   - 期待される出力（ファイルの作成・更新、コマンドの実行結果など）を明示する

5. **ツールやファイル操作を具体的に指定する**
   - 使うツール: `grep`, `read`, `write`, `edit` など
   - 対象ファイル: フルパスで指定
   - 具体的なコマンド例を示す

### 記録方法
- 各ステップの微細分割結果は `STEP[N]_BREAKDOWN.md` として保存する
- Nはステップ番号（1埋めの2桁: STEP01_BREAKDOWN.md, STEP02_BREAKDOWN.md, ...）
- 作成済みのステップを参照しながら形式を合わせる

### マイクロステップの書き方テンプレート
```
#### ステップ[N]-X: [具体的なアクションの説明]
- **アクション**: [何をするかを具体的に]
- **確認**: [どうすれば完了したかを確認できるかを具体的に]
- **ツール**: [使うツールがある場合]（例: `grep -n "pattern" /path/to/file`）
- **出力**: [何を生成/記録するかがある場合]（例: ファイルへの書き込み内容）
```

## 作業の流れ

1. 次の未完了ステップから順に処理する（ステップ13から）
2. IMPLEMENTATION_PLAN_CODE_REVIEW_48_STEPS.md を確認して対象ステップを決定
3. マイクロステップ文書を作成する（ファイル名: `STEP[N]_BREAKDOWN.md`）
4. 文書に従って順にマイクロステップを実行する
5. 各マイクロステップの完了を確認し、記録する
6. すべてのマイクロステップが完了したら、元のステップは完了とする
7. 次のステップに進む

## 進捗の確認方法

作業の進捗を確認するには：
- `ls STEP*_BREAKDOWN.md` で作成済みのマイクロステップ文書をリスト表示
- 各ファイルの内容を確認して、どのステップまで完了したかを把握
- 未作成のステップ番号が次の作業対象

## 補足

- マイクロステップは必ずしも線形である必要がない。前後のステップを参照しながら作業してもよい。
- 詰まった場合は、より小さなステップにさらに分解するか、関連するファイルを先に確認してみる。
- 完成したマイクロステップ文書は、他の開発者が同じ作業を再現できるように十分に詳細であること。
- 疲れたら無理せず休憩を取り、また後から続けることができる。
