# Phase 2: 身軽化と構造一本化（Dead Code Purge & Refactoring） - 9つの提案

**ベース**: `plans/PHASE_ROADMAP_MASTER.md` の Phase 2 セクション（4つの既存タスク）に基づき、ゴール「認知負荷の激減と、安全で保守しやすい単一アーキテクチャの確立」に沿って、さらに5項目を追加した計9つの提案です。

---

### Phase 2 提案（計9項目）

| # | 提案項目 | 目的・根拠 |
|---|----------|-----------|
| 1 | **`pyproject.toml` omit 指定のデッドモジュール（71ファイル・3,680行）の物理削除** | 既存タスク。omit対象は実質的に未使用のため、物理削除でリポジトリサイズ・クローン時間・IDEインデックス負荷を削減。 |
| 2 | **移行済みシムの完全撤廃（`src/agent/`、`src/services/age_client.py`、旧 `writing_service.py` 類）** | 既存タスク。シムは間接レイヤーを増やし、トレース不能性とパフォーマンスオーバーヘッドを生む。 |
| 3 | **統一 CLI（`autonovel`）への一本化と旧個別スクリプト（`dsp-balance` 等）の整理** | 既存タスク。エントリポイントの散在はユーザー混乱とドキュメント維持コストを増大。 |
| 4 | **データベース層の接続ラッパーハック撤廃** | 既存タスク。ラッパーは抽象化の恩恵を受けずに依存注入を妨げ、テスト困難性の原因。 |
| **5** | **重複ユーティリティ・ヘルパー関数の統合削除（`utils/`、`helpers/` ディレクトリ横断調査）** | 同一機能の複数実装はバグの温床。「DRY原則」の徹保で修正漏れを防止し、変更影響範囲を特定可能にする。 |
| **6** | **設定ファイルの二重化・三重化解消（`.env.example`、`config/`、`conf/`、`settings/` 等の統合）** | 環境変数・設定値の真偽を確認するために複数場所をチェックする認知負荷を除去。単一真実のソース(SSOT)を設定にも適用。 |
| **7** | **機能フラグ・トグルコードの完全除去（廃止済み機能の条件分岐残滓）** | 死にコードと同じく、フラグが常に同じ値なら条件分岐そのものがノイズ。ブランチ予測ミスとテストケース増加を防止。 |
| **8** | **コメントアウトコード・デバッグ残滓の一掃（`// TODO`、`// FIXME`、`print()`、`ipdb.set_trace()` 等の調査・除去）** | 読み手に「これは有効か？」と判断させる要素は認知オーバーヘッド。実行可能なコードのみを保持し、意図はissueトラッカーに委譲。 |
| **9** | **テストフィクスチャ・モックの廃止機能対応分離・削除（`tests/` 内の死にテストと同様に扱う）** | 削除対象機能に依存するテストは偽陽性を生むか、メンテナンスコストのみを発生させる。テストスイートの信頼性と高速化のために分離/削除。 |

### 採用時の次のアクション案

1. **項目 5・6・7・8・9** を `plans/PHASE_ROADMAP_MASTER.md` の Phase 2 セクションに追記（番号を振り直し）
2. **項目 5 用調査スクリプト** 作成検討:
   - `scripts/find_duplicate_functions.py`: AST パースで同一シグニチャ・同一ロジック関数検出
   - `scripts/find_similar_names.py`: ファイル名・関数名の類似度で候補列挙
3. **項目 6 用統合方針** 事前決定:
   - 設定の優先順位: 環境変数 > `.env` > `config/default.yaml` > コードハードコーディング
   - 統合場所例: `config/` ディレクトリに YAML ファイル集約
4. **項目 7 用検出方法**:
   - `git grep -n "FEATURE_" -- src/` または `git grep -n "if.*ENABLED" -- src/`
   - 定数定義箇所を追跡し、常に同じ値なら条件分岐ごと削除
5. **項目 8 用クリーニングスクリプト** 作成検討:
   - `scripts/remove_debug_statements.py`: 特定パターンの行を削除（注意: コメント内は除外）
   - `git grep -n "TODO\|FIXME\|XXX\|HACK" -- src/` でissue作成または即時対応
