# 詳細実装計画書: CI/CD・レビュー・本番監視強化 (plan1230)

## 目的
変更による既存機能喪失を防止するため、以下3つの改善点を実装する。
1. CI/CDパイプラインの修正（失敗を成功扱いしない）
2. プルリクエストレビュープロセスの強化
3. 本番環境でのインシデント検知強化

## 前提条件
- リポジトリのルートは `E:\hhh`
- 既存のCIは `.github/workflows/ci.yml`
- プルリクエストテンプレートは `.github/PULL_REQUEST_TEMPLATE.md`（存在しない場合は新規作成）
- 本番監視はPrometheus/Grafanaを前提とする（導入済みと仮定）

## ステップ一覧（1～24）

### フェーズ1: CI/CDパイプライン修正
1. `.github/workflows/ci.yml` をバックアップ: `cp .github/workflows/ci.yml .github/workflows/ci.yml.bak`
2. ファイルを開き、各ジョブの `continue-on-error: true` を削除する準備
3. `lint` ジョブから `continue-on-error: true` を削除
4. `typecheck` ジョブから `continue-on-error: true` を削除
5. `black-check` ジョブから `continue-on-error: true` を削除
6. `test-unit` ジョブから `continue-on-error: true` を削除
7. `test-integration` ジョブから `continue-on-error: true` を削除
8. `test-contract` ジョブから `continue-on-error: true` を削除
9. `test-migration` ジョブから `continue-on-error: true` を削除
10. `test-perf` ジョブから `continue-on-error: true` を削除
11. `frontend-test` ジョブから `continue-on-error: true` を削除
12. `build` ジョブの `if:` 条件は変更せず（mainブランチプッシュ時のみ実行）
13. ファイルを保存し、コミット用ステージに追加: `git add .github/workflows/ci.yml`
14. コミットメッセージで「Fix CI: remove continue-on-error to fail fast」としてコミット
15. ブランチを作成しリモートにプッシュし、プルリクエストを作成（レビュー用）

### フェーズ2: PRレビュープロセス強化
16. プルリクエストテンプレートディレクトリが存在しない場合は作成: `mkdir -p .github`
17. `.github/PULL_REQUEST_TEMPLATE.md` を新規作成し、以下の内容を記述:
   ```
   ## 概要
   - 変更の目的と影響範囲を簡潔に説明

   ## 関連 issue
   - closes #xxxx

   ## テスト追加・変更点の影響範囲
   - [ ] 新規テストを追加したか（または既存テストを更新したか）
   - [ ] 影響を受ける可能性がある機能をリストアップし、手動/自動テストで確認したか
   - [ ] ブック生成フロー全体の喫煙テストを実施したか

   ## 機能フラグの両状態テスト
   - [ ] 関連する機能フラグがある場合、ON/OFF両方で動作確認したか
   - [ ] フラグ OFF 時の既存挙動が変わらないことを確認したか

   ## レビューチェックリスト
   - [ ] コードスタイル（ruff・black）違反がないか
   - [ ] 型エラー（mypy）がないか
   - [ ] ドキュメントコメントは必要に応じて更新したか
   - [ ] セキュリティ上の懸念はないか
   - [ ] パフォーマンスへの影響は評価したか
   ```
18. ファイルを保存し、ステージに追加: `git add .github/PULL_REQUEST_TEMPLATE.md`
19. コミットメッセージで「Add PR template with review checklist」としてコミット
20. 同ブランチにプッシュし、プルリクエストを更新

### フェーズ3: 本番環境でのインシデント検知強化
21. 本番用のアラート設定ファイル（例: `monitoring/alert_rules.yml`）を作成し、以下のルールを追加:
   ```yaml
   groups:
   - name: autonovel.rules
     rules:
     - alert: BookScoreDrop
       expr: avg_over_time(book_score_overall[1h]) < 75
       for: 5m
       labels:
         severity: warning
       annotations:
         summary: "BookScore平均点が75を下回っています"
         description: "過去1時間のBookScore平均点が {{ $value }} です。"
     - alert: AuditScoreAnomaly
       expr: | 
         (avg_over_time(audit_score_consistency[1h]) < 60) or
         (avg_over_time(audit_score_creativity[1h]) < 60)
       for: 10m
       labels:
         severity: critical
       annotations:
         summary: "監査スコアが異常に低下しています"
         description: "一貫性または創造性のスコアが60を下回っています。"
     - alert: ErrorRateSpike
       expr: rate(http_requests_total{status=~"5.."}[5m]) > 0.05
       for: 2m
       labels:
         severity: critical
       annotations:
         summary: "5xx エラーレートが急上昇しています"
         description: "5分間の5xxエラーレートが {{ $value }} を超えています。"
   ```
22. 設定ファイルをステージに追加: `git add monitoring/alert_rules.yml`
23. コミットメッセージで「Add Prometheus alert rules for production monitoring」としてコミット
24. ブランチにプッシュし、プルリクエストを作成（または既存のPRに squash merge して一つにまとめても可）

## 完了基準
- すべてのCIジョブが `continue-on-error: true` を持たず、失敗時に赤になる
- プルリクエスト作成時にテンプレートが自動挿入され、レビューチェックリストが表示される
- 本番環境にアラート ルールが適用され、メトリクス異常時に通知が発火する
