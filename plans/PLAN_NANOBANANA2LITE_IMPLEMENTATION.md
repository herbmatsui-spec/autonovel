# ナノバナナ2ライト実装可能性評価および詳細計画書（改定版）

## エグゼクティブサマリー
**ナノバナナ2ライトによる「1話1枚生成（24コマ漫画シート一括生成）」＋「写植（オプション）」パイプラインへの刷新計画**です。
従来の「24コマ個別生成・合成」から「1話につき1枚のイラストとして24コマ漫画を一括生成」する方式へと移行することで、APIコストを**約96%削減（40話で約$1.36、無料枠なら実質$0）**し、生成時間を**数時間から数分へ劇的に短縮**します。

## ナノバナナ2ライトの主要特性とコスト試算

| 特性 | 仕様 / 特徴 | 本パイプラインでの位置付け |
|---|---|---|
| **ベースモデル** | Gemini 3.1 Flash-Lite Image | 高速生成・強力なプロンプト＆参照画像理解 |
| **生成速度** | ~4秒 / 1画像 | 40話分がわずか約160秒（3分未満）で完了 |
| **コスト** | ~$0.034 / 1画像 | **1話1枚 = $0.034、40話 = 約$1.36**（無料枠利用なら$0） |
| **参照画像** | 最大10枚まで同時指定可能 | キャラクター・絵柄の一貫性担保の要 |
| **ネイティブ解像度** | 1024px (1K) | 生成後にローカル超解像（無料）で4Kへアップスケール |
| **アスペクト比** | 15種類（1:1, 4:3, 3:4, 16:9等） | マンガシート全体（3:4 または 2:3）の構図に最適化 |
| **画像編集** | 自然言語インペイント / 編集 | 万一特定コマのみ崩れた場合の部分修復に活用 |

## フェーズ別詳細実装計画

### フェーズ0: マスターアセット準備（Day 1）
**目的**: キャラクターの一貫性をナノバナナ2ライトに維持させるための「マスター参照シート」を作成・固定。

#### 0.1 キャラクター参照シート生成
```text
prompt: "character model sheet, [character_name], multiple poses and expressions, 
         front back side views, manga style, clean bold lineart, flat colors, 
         white background, professional anime character sheet --ar 1:1"
```
* 各メインキャラについて生成し、ベストな1枚を `char_ref/[name]_master.png` として確定。
* 1度確定した参照シートは全40話で共通利用するため、初回のみの低コスト投資。

---

### フェーズ1: 1枚マンガシート用プロンプト＆参照設計（Day 2）

#### 1.1 プロンプト構造（24コマ一括生成用）
画像生成AIに文字を描かせると文字化け・崩れの原因になるため、**「サイレント漫画（文字・フキダシなし）」**として生成します。

```text
(char_ref/protagonist_master.png)
manga sheet, sequential comic strip, 24 panels in a 4x6 clean grid layout,
telling the story of [short_episode_summary],
consistent character appearance with reference image,
manga art style, sharp lineart, screentone shading, dynamic angles,
--no speech bubbles, no text, no captions, no watermark --ar 3:4
```

#### 1.2 ネガティブプロンプト
```text
negative_prompt: "text, speech bubbles, blurry, deformed panels, irregular messy grid, 
                   color bleeding, 3d render, photo, low resolution"
```

---

### フェーズ2: バッチ生成＆品質ゲート（Day 3-4）

#### 2.1 1話1枚バッチ処理フロー
1. 話ごとの概要・起承転結からプロンプトを構築。
2. ナノバナナ2ライトAPIを呼び出し（1話あたり1リクエスト）。
3. 品質ゲートスクリプトで以下を自動判定：
   * **グリッド認識**: エッジ検出で24コマ（4×6）のおおまかな枠構造が存在するか。
   * **キャラ類似度**: CLIPで参照画像と出力全体の特徴類似度を測定。
4. **部分修正（Inpaint）フォールバック**:
   * 1〜2コマだけ顔が崩れている場合、全体を再生成（リロール）するのではなく、ナノバナナ2ライトの編集指示で「該当コマのみ修正」を行いコストを最小化。

---

### フェーズ3: ローカル超解像（解像度補完パイプライン）（Day 5）
**目的**: 1024pxの中に24コマを描いた際の解像度不足（1コマ約170px）を、ローカル無料ツールで完全補完。

* **使用ツール**: Real-ESRGAN / SwinIR（オープンソース、商用利用可、ローカルGPU/CPU実行）
* **処理内容**:
  * 1024px → **4096px（4K）** または **8192px（8K）** に拡大。
  * マンガ用の線画モデル（`RealESRGAN_x4plus_anime_6B`）を採用し、線の滲みを防止してシャープな白黒・スクリーントーンを再現。
* **コスト**: **完全無料（$0）**

---

### フェーズ4: 【オプション】写植・フキダシ合成（Day 6）
**位置付け**: 今回はオプション（必要に応じて有効化）。サイレント漫画として運用する場合はスキップ可能。

* **実装方式**:
  * ストーリーボードJSONのセリフデータを読み込み。
  * Python（Pillow）またはSVGテンプレートエンジンを用いて、各コマの位置に対応したフキダシと日本語テキスト（フリーフォント：源暎アンチック等）をオーバーレイ描画。
* **メリット**:
  * 画像生成AIの文字崩れを100%回避。
  * 多言語ローカライズ（日本語／英語）がテキスト差し替えだけで瞬時に可能。
* **コスト**: **完全無料（$0）**

---

### フェーズ5: 40話スケール運用とパイプライン実装（Day 7）

#### 5.1 ディレクトリ構成
```
nanobanana_manga_pipeline/
├── config/
│   ├── characters.yaml         # キャラクター定義・参照画像パス
│   └── episodes/               # 1〜40話のプロンプト・シナリオ
├── src/
│   ├── client.py               # ナノバナナ2ライト APIクライアント
│   ├── prompt_generator.py     # 24コママンガシート用プロンプト生成

├── output/
│   ├── raw_sheets/             # APIから直接出力された1K画像
│   ├── upscaled/               # 4K超解像済み画像

└── run_pipeline.py             # 全自動実行スクリプト
```

## リスク管理と対応策

| 想定リスク | 影響度 | 具体的対策 |
|---|:---:|---|
| **24コマの枠が乱れる・コマ数がずれる** | 中 | プロンプトで `4x6 clean grid layout` を強調。または背景枠線テンプレートを初期参照画像として与える。 |
| **コマ内のキャラの顔が潰れる** | 中 | フェーズ3のReal-ESRGAN（anime特化モデル）で4K化して線画を復元。 |
| **ストーリー展開がプロンプト1本で伝わらない** | 低 | 24コマ全体の起承転結を簡潔に要約し、プロンプトのAttention（注目度）が散らないよう整理。 |
| **API費用・制限** | 極小 | 1話1枚のため40話でも40リクエスト（約$1.36）。Google AI Studio無料枠なら完全無料。 |
