# v3.6 UI/UX Refactor Implementation Plan

## Overview
このプランは、UI/UX 全体の抜本的リファクタリングを **3 つの提案** に分割し、**1 から 72** のステップで実装・テスト・デプロイまでを体系的に管理します。

| 提案 | 内容 | ステップ範囲 |
|------|------|--------------|
| 1 | タブ構造のモジュール化と遅延ロード | 1‑24 |
| 2 | デザインシステムの統一とアクセシビリティ向上 | 25‑48 |
| 3 | 状態管理・データフェッチのスコープ最適化 | 49‑72 |

---

## Proposal 1 – Tab Modularization & Lazy Loading (Steps 1‑24)

1. **コードベーススキャン** – `src/frontend/src/components/tabs/**/*.tsx` を `grep -r "export"` で一覧取得し、現行タブのエクスポート状況を把握。
2. **React Router 追加** – `npm i react-router-dom@6` をインストールし、`frontend/src/router.tsx` にベースルーティングを作成。
3. **ルート定義** – 各タブを `/books`, `/write`, `/plots` などのパスへマッピングし、`<Route>` コンポーネントで遅延インポート (`React.lazy`) を設定。
4. **`App.tsx` 簡素化** – ルーティング `<Outlet />` のみ残し、共通 UI（`Sidebar`、`HealthGate`）は上位レイアウトに保持。
5. **共通レイアウトコンポーネント** – `src/components/layout/AppLayout.tsx` を新規作成し、ヘッダー・サイドバー・メインエリアをラップ。
6. **`Sidebar` クリックハンドラ** – `navigate()` 呼び出しに置き換え、URL にタブ状態が反映されるよう変更。
7. **タブコンポーネントの `export default`** – 各タブをデフォルトエクスポートに統一し、遅延ロードが容易になるようリファクタ。
8. **型定義整理** – タブ固有の `Props` を `TabProps` インターフェースに統一し、`AppLayout` が `ReactNode` を受け取る形に更新。
9. **Zustand ストア整理** – `activeTab` を `useProjectStore` から削除し、`react-router` の `location.pathname` に依存させる。
10. **テスト用モックルート** – `tests/unit/router.test.tsx` で `MemoryRouter` を用いたタブ遷移テストを作成。
11. **コード分割のビルド設定** – `vite.config.ts` の `manualChunks` に `react-router-dom` など主要ライブラリを分割指定。
12. **エラーバウンダリ** – すべての遅延タブを `<Suspense fallback={<LoadingSpinner />}>` で包み、ロード失敗時の UI を統一。
13. **Lazy Load のパフォーマンス測定** – `web-vitals` で初回ロード LCP を測定し、目標 2 秒以下を設定。
14. **CI ビルドステップ更新** – `npm run build` 時に `vite build --ssrManifest` が成功することを確認。
15. **ステージングデプロイ** – `feature/tab-modularization` ブランチを作成し、Vercel (or similar) にプレビュー環境を自動デプロイ。
16. **ユーザビリティテスト** – 社内 QA がタブ切替での遅延ロード挙動を 5 回確認し、問題が無いことをレポート。
17. **コードレビュー** – Pull Request を作成し、フロントエンドチームに 2 名以上の承認を取得。
18. **マージ** – 承認後 `main` にマージし、GitHub Actions が自動デプロイを実行。
19. **本番環境での計測** – CloudWatch (or equivalent) で実際の LCP と TTFB を取得し、設計目標と比較。
20. **モニタリングアラート** – タブ遅延ロードが 5 秒を超えた場合に Slack 通知するアラートを追加。
21. **ロールバック手順書** – 失敗時に `git revert <commit>` で旧 `App.tsx` に戻す手順を `docs/rollback/tab_modularization.md` に記載。
22. **ドキュメント更新** – `docs/architecture/frontend.md` に新しいルーティング構成図を追記。
23. **リリースノート** – `CHANGELOG.md` に "Implemented lazy‑loaded tab routing (v3.6)" を追加。
24. **完了チェック** – すべてのステップが完了したことを `plans/v3.6_completion_checklist.md` に記録。

## Proposal 2 – Design System Unification & Accessibility (Steps 25‑48)

25. **デザイントークン定義** – `tailwind.config.js` の `theme.extend` にカラー、スペーシング、フォントサイズのトークンを `--color-primary` 等の CSS カスタムプロパティとして定義。
26. **Atomic Design フォルダ構造作成** – `src/components/ui/atoms`, `molecules`, `organisms` を作成し、現行 UI コンポーネントをカテゴリ別に移動。
27. **共通 Button コンポーネント作成** – `atoms/Button.tsx` を実装し、`className` にトークンを使用、`variant` prop でスタイル切替、必須 `aria-label` を自動付与。
28. **Input コンポーネント統一** – `atoms/Input.tsx` を作成し、`type`, `placeholder`, `aria-*` のプロパティを受け取るよう実装。
29. **Dialog コンポーネント HOC** – `molecules/Dialog.tsx` に `withA11y` HOC を適用し、`role="dialog"` と `aria-modal="true"` を保証。
30. **既存 UI のラッパー化** – `src/components/ui/button.tsx` など旧コンポーネントを新 `Button` への再エクスポートに置き換えるスクリプト (`jscodeshift`) を作成し、全プロジェクトで一括置換。
31. **テーマ切替ロジック** – `src/store/useThemeStore.ts` を導入し、`useEffect` で `document.documentElement.style.setProperty` を更新、ダークモード切替を実装。
32. **アクセシビリティレビュー** – axe-core CLI (`npx axe`) を CI に組み込み、プルリクエストごとにアクセシビリティレポートを生成。
33. **ARIA ラベル自動生成ユーティリティ** – `src/utils/a11y.ts` に `generateAriaLabel(text: string): string` を実装し、ボタン等のデフォルトラベルに利用。
34. **Storybook 導入** – `npm i -D @storybook/react` でセットアップし、全 Atom/Molecule の UI カタログを作成。
35. **ビジュアルリグレッションテスト** – Storybook の Chromatic 連携で UI 変更時に自動スナップショット比較。
36. **コンポーネントテスト** – `tests/unit/ui/button.test.tsx` などで `@testing-library/react` を使用し、キーボード操作・スクリーンリーダー読み上げを検証。
37. **デザインシステムドキュメント** – `docs/design-system.md` にトークン、コンポーネント API、アクセシビリティガイドラインを記述。
38. **CI の linter ルール追加** – `.pre-commit-config.yaml` に `eslint-plugin-jsx-a11y` を有効化し、未付与属性をエラー化。
39. **プロダクションビルド検証** – `npm run build` 後に `purgecss` がトークンを除外しないか確認し、必要なら `safelist` を設定。
40. **コードレビュー** – UI チームに対し Pull Request を提出し、デザインガイドとアクセシビリティの遵守を確認。
41. **マージ** – 承認後 `main` にマージし、CI がデプロイ。
42. **本番デプロイ後のアクセシビリティモニタリング** – Lighthouse CI を nightly 実行し、AA/AAA スコアが 90 以上を維持。
43. **カスタムフォント統合** – `src/assets/fonts` にフォントを追加し、Tailwind の `fontFamily` にマッピング。
44. **ローディングスピナー統一** – `atoms/LoadingSpinner.tsx` を作成し、全ページで同一スピナーを使用。
45. **エラーメッセージコンポーネント** – `atoms/ErrorBanner.tsx` に `role="alert"` を付与し、スタイルをトークンベースに変更。
46. **モバイルレスポンシブテスト** – BrowserStack で主要デバイス 5 種類を自動テストし、レイアウト崩れが無いことを CI で検証。
47. **ドキュメントリリースノート** – `CHANGELOG.md` に "Unified design system with accessibility improvements (v3.6)" を追記。
48. **完了チェック** – ステップ 25‑48 が完了したことを `plans/v3.6_completion_checklist.md` に反映。

## Proposal 3 – State Management & Data Fetch Consolidation (Steps 49‑72)

49. **現行 Zustand ストア調査** – `src/store/**/*.ts` を `grep -r "create"` で列挙し、データ層と UI 層の分離ポイントをマッピング。
50. **Zustand スライス設計** – `bookSlice`, `taskSlice`, `uiSlice` を `src/store/slices/` に作成し、各スライスの public API を定義。
51. **React Query 追加** – `npm i @tanstack/react-query` をインストールし、`src/api/` 配下にフェッチ関数 (`fetchBooks`, `fetchBookDetails`, `fetchPlots`) を実装。
52. **既存フック置換** – `useBooks`, `useBookDetails` などを React Query の `useQuery` ラッパーに書き換え、ローディング・エラーハンドリングを統一。
53. **Zustand → React Query データ同期** – 各スライスは `useQuery` の `onSuccess` で状態を更新し、二重保持を防止。
54. **Mutations の統一** – `useCreateBook`, `useUpdateChapter` などを `useMutation` に統合し、成功時に対象スライスを自動更新。
55. **エラーハンドリングユーティリティ** – `src/core/error_handler.ts` に `handleQueryError` を実装し、全 Query の `onError` で共通ロギング・UI エラーバナー表示を行う。
56. **キャッシュポリシー設定** – `staleTime` と `cacheTime` を用途別に設定し、書籍リストは長め、ストリーミングログは短めに調整。
57. **テスト用 Mock Server** – `msw` (Mock Service Worker) を導入し、`tests/unit/api` で API 呼び出しをモック、CI でネットワーク依存を排除。
58. **Zustand の廃止対象コード削除** – `useProjectStore` の `activeTab` 関連コードを削除し、`router` が唯一のソースになるよう整理。
59. **型安全化** – `src/types/api.d.ts` に API レスポンス型を定義し、React Query のジェネリクスで使用。
60. **CI のカバレッジ基準** – `coverage run -m pytest` 後、`coverage report` が 90% 以上になるようテストを追加。
61. **Storybook の Data Provider** – `MockProvider` コンポーネントで React Query の `QueryClientProvider` とモックデータを提供し、UI コンポーネント単体テストを可能にする。
62. **タスクモニタリングの統合** – `useTaskMonitor` から取得した状態を `taskSlice` に保存し、他コンポーネントが `useTaskStore` だけで参照可能に。
63. **ローディングインジケータ統一** – `uiSlice` に `globalLoading` フラグを追加し、全ページで `LoadingSpinner` を一括制御。
64. **パフォーマンス測定** – `react-profiler` でデータ取得とステート更新のオーバーヘッドを測定し、30 ms 未満に抑える目標を設定。
65. **コードレビュー** – DB 層とフロント層の統合 PR を作成し、2 名以上のレビューを取得。
66. **マージ** – 承認後 `main` にマージし、CI が自動デプロイ。
67. **本番環境でのデータフロー検証** – ステージングで `network` タブを観測し、React Query のキャッシュヒット率が 80% 以上であることを確認。
68. **モニタリングアラート** – React Query の `isError` が 5 分間に 10 回以上発生した場合に PagerDuty 通知を設定。
69. **ロールバック手順書** – `scripts/rollback_state.sh` を作成し、旧 Zustand データを復元できる手順を記載。
70. **ドキュメント更新** – `docs/architecture/state_management.md` に新スライス構成と React Query の使用方法を追記。
71. **リリースノート** – `CHANGELOG.md` に "Consolidated state management with React Query (v3.6)" を追加。
72. **完了チェック** – 全 72 ステップが完了したことを `plans/v3.6_completion_checklist.md` にマークし、リリース完了を報告。
