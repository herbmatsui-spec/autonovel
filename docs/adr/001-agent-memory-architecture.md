# ADR 001: 階層的エージェントメモリ (MemGPT流) アーキテクチャの採用

## ステータス
承認・実装完了 (Accepted & Implemented)

## コンテキスト
長編小説の自律執筆において、キャラクターの感情状態や人間関係の変遷はエピソードを跨いで継続的に保持・更新される必要があります。
しかし、LLMのコンテキスト長には限界があり、全履歴をプロンプトに注入し続けるとトークンコストの肥大化および注意散漫（Needle-in-a-haystack問題）が発生します。

## 決定事項
MemGPTの階層的メモリ設計を導入し、エージェントメモリを3層に分離しました：
1. **CoreMemory**: システムプロンプトに常駐する最小限の重要感情・関係性・フック。
2. **WorkingMemory**: 現在のエピソード/シーンの進行ビートを保持する揮発性スタック。
3. **ArchivalMemory**: 過去の全イベント・感情要約を保持し、オンデマンドで検索可能な外部記憶。

エージェント自身にツール（Function Calling）を提供し、自律的な感情更新と想起を行わせます。

## 結果・影響
- **利点**:
  - トークン消費量を一定（2000トークン以下）に抑えながら、100話以上の長編でもキャラクター感情の一貫性を維持可能。
  - Week 4 の融合レイヤーとシームレスに連携し、作者指定と自動推論の矛盾を自動調停。
  - IFルートやプロット分岐に対して、ブランチメモリとして完全な独立性を確保。
- **トレードオフ**:
  - ツール呼び出しオーバーヘッド（Function Callingのレイテンシ）が生じる。
