# ADR 0002: AIオーケストレーションフレームワークへの移行方針 (LangGraph)

## Context
現在のAI執筆パイプライン（`GenerationLoopManager`）は、複雑な手続き型ロジックで制御されており、リトライ制御や状態遷移の可視化が困難である。

## Decision
自前で実装している制御ループを廃止し、LangGraph を利用したグラフベースのオーケストレーションへ移行する。
1. 各工程（プロット生成、執筆、監査、修正）をノードとして定義する。
2. 条件分岐（リトライ判定、品質チェック）をグラフのエッジ（遷移）として表現する。

## Consequences
- フローの可視化が可能になり、デバッグが容易になる。
- 複雑な条件分岐やリトライ制御をフレームワーク標準の機能に委譲できる。
- コードベースがスッキリし、個別のノード（エージェント）の開発に集中できる。

## Proposal C: ワークフロー主導のプロット再構築パイプライン

再構築ロジックの重複を排除するため、以下の責務分割を採用する。

- `PlanningAgent` : アーク生成 (`generate_arcs`) のみを担当。
- `PlotAgent` : プロット展開 (`expand_plots`) のみを担当。
- `PlotRebuildWorkflow` : 両者を組み合わせた 5 ステップ・パイプラインの
  オーケストレーターとして再構築を実行する。

`PlotAgent.rebuild_hegemony_plot` および `PlanningAgentRebuildMixin` は削除され、
再構築の重複実装は解消された。各ステップは失敗してもパイプラインを停止せず、
可能な範囲で部分結果を返す (graceful degradation)。
