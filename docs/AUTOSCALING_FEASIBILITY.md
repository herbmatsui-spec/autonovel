# 自動スケーリング検討

## Docker Compose の `scale` ディレクティブの限界
- Docker Compose の `scale` コマンドは、サービスのレプリカ数を手動で変更する。
- 自動スケーリングには、メトリクスに基づいて自動的にレプリカ数を調整する仕組みが必要。
- Docker Compose 単体では、自動スケーリングの機能は提供されていない。

## Kubernetes または Docker Swarm への移行検討
- Kubernetes: 堅牢な自動スケーリング機能 (HPA, VPA) を提供。
- Docker Swarm: 組み込みのスケーリング機能はあるが、カスタムメトリクスベースのスケーリングは限定的。

## メトリクスベースの自動スケーリング
- スケーリングのトリガーとなるメトリクスの例:
  - CPU 使用率
  - メモリ使用率
  - キューの長さ (例えば、RQ または Celery のキュー)
  - リクエスト遅延またはスループット

## 推奨
- Phase 4 では、Docker Compose で固定レプリカ数を使用し、シンプルさを保つ。
- Phase 5 以降で、Kubernetes または Docker Swarm への移行を検討し、自動スケーリングを導入する。
- 移行のステップ:
  1. サービスをコンテナ化し、依存関係を明確にする（既に Docker Compose で完了）。
  2. Kubernetes マニフェストまたは Docker Swarm サービス定義を作成。
  3. メトリクス収集プロメテウスなどを導入し、HPA を設定。
