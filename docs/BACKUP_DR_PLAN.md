# バックアップ・災害復旧計画

## バックアップ種類
### 論理ダンプ
- ツール: `pg_dump`
- 頻度: 毎日夜間（例: 02:00）
- 保存先: オフサイトオブジェクトストレージ（S3, GCS など）
- 保持期間: 30 日

### ファイルシステムスナップショット
- ツール: Docker ボリュームスナップショットまたは LVM スナップショット
- 頻度: 毎時
- 保存先: オフサイトオブジェクトストレージ
- 保持期間: 7 日

## 保存先
- オフサイトオブジェクトストレージ（例: AWS S3, Google Cloud Storage, Azure Blob Storage）。
- バケットはバージョニングとライフサイクルポリシーを有効にする。

## リストア手順
1. 最新スナップショットからボリュームを復元
   - ファイルシステムスナップショットからボリュームを復元し、データベースディレクトリを上書き。
2. 必要ならポイントインタイムリカバリのために WAL ログを適用
   - `pg_walreplay` または `pg_basebackup` を使用して、スナップショット時点からの WAL ログを適用。
3. アプリケーションを起動し、整合性チェック
   - データベースの整合性チェック (`pg_checksums` または `pg_dump` + `pg_restore` を使用した論理チェック)。
   - アプリケーションの smoke テストを実行。

## RTO (Recovery Time Objective): 30 分
## RPO (Recovery Point Objective): 15 分

## 訓練スクリプト雛形
- `scripts/drill_restore.py`: リストア手順を自動化するスクリプトの雛形。
- 実際の環境に合わせてカスタマイズすること。
