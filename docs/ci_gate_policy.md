# CI ブロッキングゲート ポリシー

## 基本方針

新規コードは常にゲートを通過しなければマージできない。既存の負債（technical debt）は
段階的に減らし、最終的に全リポジトリでブロッキング化する。

## ルール

### 1. 新規・変更ファイル（即時ブロッキング）

- `ruff format --check` … 失敗ならマージ不可
- `ruff check` … 失敗ならマージ不可
- `mypy --strict`（新規ファイルのみ、今後追加） … 失敗ならマージ不可

これらは PR ごとに変更された `.py` ファイルだけを対象とし、既存の負債を新規コードで
増やさないことを保証する。

### 2. 全リポジトリ（負債バーンダウン後・ブロッキング）

以下を満たした時点で、`.github/workflows/ci.yml` の `lint` / `typecheck` ジョブから
`continue-on-error: true` を削除し、全量ブロッキング化する。

| 指標 | 目標値 |
|------|--------|
| `ruff check src/ tests/` エラー数 | 0 |
| `mypy --strict src/` エラー数 | 0 |

## 例外（一時的免除）

緊急ホットフィックス等で一時的にゲートを通したい場合は、CI 上で明示的に
`continue-on-error` を付与するのではなく、Issue を起票し後日修正タスクを登録する。
