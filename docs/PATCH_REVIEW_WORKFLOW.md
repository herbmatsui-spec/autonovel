# Patch Review Workflow - ユーザー操作ガイド

## 概要

本ドキュメントでは、自動小説生成システムにおける**矛盾レポート確認・承認ワークフロー**の操作方法を説明します。

監査エージェント（AuditAgent）が執筆内容の矛盾を検出した際、自動的に WritingAgent へリトライさせるのではなく、**ユーザーが矛盾内容を確認し、承認・差し戻し・修正案提示**を行えるようになりました。

---

## ワークフロー全体図

```
┌─────────────┐     監査実行      ┌─────────────┐
│ WritingAgent │ ──────────────► │  AuditAgent  │
│  (執筆)      │                 │  (監査)      │
└─────────────┘                 └──────┬──────┘
                                        │
                              矛盾あり  │
                                        ▼
                              ┌───────────────────┐
                              │  PatchReview 作成  │
                              │  (ステータス:      │
                              │   under_review)   │
                              └─────────┬─────────┘
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
            ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
            │   承認      │     │   差し戻し   │     │ 修正案提示  │
            │ (approved)  │     │ (rejected)  │     │(needs_rev.) │
            └──────┬──────┘     └──────┬──────┘     └──────┬──────┘
                   │                   │                   │
                   ▼                   ▼                   ▼
            次の処理へ          Healing/修復        再レビュー
            (dogfeed等)          フェーズへ          待ち
```

## 操作手順

### 1. レビュー待ち一覧の確認

**エディタ画面のサイドバー**に「レビュー待ち: N 件」というバッジが表示されます。

1. サイドバーの **「矛盾レポート」** タブをクリック
2. または、バッジをクリックしてモーダルを開く

### 2. 矛盾レポートの確認

**矛盾レポートパネル**には3つのタブがあります：

#### 【矛盾一覧】タブ
- 検出された矛盾の一覧がカード形式で表示
- 各カードには以下の情報：
  - **カテゴリ**: 論理整合性 / 因果律 / 能力整合性 / AI感 / プロット構造
  - **重要度**: 緊急(赤) / 高(橙) / 中(黄) / 低(緑)
  - **説明**: 具体的な矛盾内容
  - **該当フィールド**: 設定のどの箇所がブレているか（パス形式）
  - **信頼度**: 監査システムの判定信頼度

カードをクリックすると **【詳細diff】タブ** に切り替わり、詳細が表示されます。

#### 【詳細diff】タブ
選択した矛盾の詳細表示：
- **現在の値 / 推奨値** の左右対比 diff
- **過去の証拠**: 過去の話で設定されていた内容
- **現在の証拠**: 今回の話で書かれている内容
- **次回への制約**: 次話以降で守るべき制約条件

#### 【アクション】タブ
3つのアクションボタン：

| ボタン | 用途 | 必須入力 |
|--------|------|----------|
| ✅ **承認して続行** | 推奨修正案を受け入れ、次の処理へ進む | なし |
| ❌ **差し戻し** | 矛盾指摘に不同意、修復フェーズへ戻す | **理由（必須）** |
| 🔄 **修正案を提示** | 推奨値を修正して再レビュー要求 | **修正内容（必須）、理由（任意）** |

---

## アクション別の動作詳細

### ✅ 承認（Approve）
1. 推奨修正案を採用
2. 関連する `AuditIssue` を `resolved` ステータスに更新
3. `WritingLangGraph` が `dogfeed` → `finalize` へ進行
4. 次話の生成が継続される

### ❌ 差し戻し（Reject）
1. ユーザーの不同意理由を記録
2. 関連する `AuditIssue` を `rejected` ステータスに更新
3. `WritingLangGraph` が `healing`（修復フェーズ）へ移行
4. 自動修復を試行し、再度監査 → それでも失敗なら再びレビュー待ち

### 🔄 修正案提示（Revise）
1. ユーザーが入力した修正案を `PatchReview.proposed_content` に反映
2. ステータスを `under_review` に戻す（再レビュー待ち）
3. ユーザー（または別のレビュアー）が再度確認・承認

## 設定変更の差分マージと学習ループ

### 手動設定変更の自動記録
エディタや Bible 管理画面で設定を手動修正すると、自動的に以下が記録されます：

1. **SettingDelta** - 変更差分（フィールドパス、旧値、新値、変更種別）
2. **SettingVersion** - 完全スナップショット（バージョン番号付きで履歴管理）

### GraphRAG への自動反映
記録された差分は非同期で以下に反映されます：
- **ChromaDB**: ベクトル検索用ドキュメントの更新
- **Knowledge Graph**: ノード/エッジ属性の更新

### ネガティブサンプル蓄積
ユーザーが **却下** した監査パターンは「ネガティブサンプル」として蓄積され、将来の監査精度向上に活用されます：

- 同種のパターンが多く却下されている → 監査閾値を緩和、warning 扱いに
- 承認されているパターン → 正例として信頼度向上

## 設定画面

### タイムアウト設定
`ProjectContext` または環境変数で調整可能：

| 設定キー | デフォルト | 説明 |
|----------|-----------|------|
| `patch_review_timeout_seconds` | 86400 (24h) | レビュー待機タイムアウト |
| `patch_review_poll_interval_seconds` | 10 | ポーリング間隔 |

タイムアウト時は自動的に `rejected` 扱いとなり、修復フェーズへ移行します。

## API リファレンス

### レビュー一覧取得
```
GET /api/patches/{book_id}/reviews
```

### レビュー詳細取得
```
GET /api/patches/reviews/{review_id}
```

### 承認
```
POST /api/patches/reviews/{review_id}/approve
Body: { "reviewer_id": "user1", "comment": "OK" }
```

### 差し戻し
```
POST /api/patches/reviews/{review_id}/reject
Body: { "reviewer_id": "user1", "comment": "理由" }
```

### 修正案提示
```
POST /api/patches/reviews/{review_id}/revise
Body: { "proposed_content": "...", "reviewer_id": "user1", "comment": "..." }
```

### 設定バージョン履歴
```
GET /api/patches/{book_id}/setting-versions
GET /api/patches/{book_id}/setting-versions/{version_number}
```

## トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| レビューが表示されない | PatchReview が作成されていない | 監査ログを確認、エラーがないか確認 |
| 承認しても進まない | `PatchReview.status` が更新されていない | API 応答を確認、ネットワークエラーがないか確認 |
| 設定変更が検索に反映されない | GraphRAG マージが未完了 | しばらく待ってから再試行、または手動再インデックス実行 |
| 同じ矛盾が繰り返し出る | 学習データが蓄積されていない | 明示的に承認/却下を行い、学習データを増やす |
