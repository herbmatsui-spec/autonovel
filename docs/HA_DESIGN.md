# 高可用性設定

## データベース: PostgreSQL のストリーミングレプリケーション
- マスターサーバー 1 台とスタンバイサーバー 1 台以上を構成。
- スタンバイサーバーは、マスターから WAL ログを受信して適用し、ホットスタンバイとして読み込みクエリを提供可能。
- フェイルオーバー: マスターがダウンした場合、スタンバイサーバーのいずれかを新しいマスターに昇格させる。
- 推奨ツール: Patroni または pgAutoFailover を使用した自動フェイルオーバー。

## ネットワーク: ロードバランサーによる冗長化
- ロードバランサー (NGINX, Traefik, HAProxy など) を使用して、複数の API サーバーインスタンスへトラフィックを分散。
- ロードバランサー自体も冗長化（アクティブ-スタンバイまたはアクティブ-アクティブ構成）。
- ヘルスチェックを使用して、異常なインスタンスをプールから自動的に削除。

## サービス: ステートレス設計
- API サーバーはステートレスであることを設計し、セッション状態をクライアントまたは外部ストレージ（Redis）に保存。
- これにより、任意のインスタンスがどのリクエストでも処理可能となり、スケーリングとフェイルオーバーが容易になる。

## フェイルオーバー
- 自動昇格スクリプトまたは監視ツール（Patroni）を使用して、データベースのフェイルオーバーを自動化。
- アプリケーションレベルでは、データベース接続の再試行ロジックを実装し、一時的な接続エラーを許容する。
