# 優先度4〜9 根本改修・技術的負債解消 実装計画書 (plan1302.md)

本計画書は、AutoNovelプロジェクトのアーキテクチャ精査において特定された【優先度 4 〜 9】の6大課題：
1. **【優先度 4】PDCA閉ループ再執筆における執筆エージェントのスタブ放置解消**
2. **【優先度 5】スキル駆動型アーキテクチャ（`manifest.yaml`）と実行パイプラインの動的結合**
3. **【優先度 6】SQLiteフォールバック時RAGの逐次Embedding再計算撲滅 & 高速ベクトル検索**
4. **【優先度 7】環境変数キー（`GEMINI_API_KEY` vs `GOOGLE_GENAI_API_KEY`）の一元化 & 認証不整合解消**
5. **【優先度 8】商用投稿（なろう・カクヨム）アダプタの非同期ワーカー分離 & 予約投稿ジョブ実装**
6. **【優先度 9】コンテキスト管理・監査ロジックの多重実装（3重スプリットブレイン）一本化**
を、低性能なLLMや自動化エージェントでも確実に1ステップずつ迷わず実装・検証できるよう、**全72の独立した小さなマイクロステップ**に分割・定義した詳細手順書です。

  - 対象ファイル: `src/agents/writing/agent.py`

### 【Phase 3: SQLiteフォールバック時RAGのEmbedding事前永続化 & 高速検索（ステップ 25 〜 36）】
**目的**: SQLiteフォールバック環境において、検索クエリのたびに全チャンクを逐次Embedding API再計算して数秒〜十数秒の遅延とトークン課金爆発を起こし、直近15件で足切りしていた問題を解決。チャンク保存時にEmbeddingを事前保存し、クエリEmbeddingとのNumPy一括ベクトル計算により全履歴からのミリ秒高速検索を実現します。

* **Step 25: `ChapterChunk` モデルの SQLite JSON 型互換性の確認**
  - 対象ファイル: `src/infrastructure/database/models/chunk.py`
  - 変更内容: `pgvector` 不在環境下でも `embedding` カラムが SQLite の `JSON`（または TEXT）型として透過的にシリアライズ・デシリアライズできることを確認・型デコレータを強化。
  - 検証: SQLite セッションで `c.embedding = [0.1, 0.2, ...]` を保存して取り出せること。

* **Step 26: チャンク登録時（`upsert_chunks`）における DB embedding カラムの同時書き込み**
  - 対象ファイル: `src/services/chunk_ingestion.py`
  - 変更内容: `upsert_chunks` 内で計算した埋め込みベクトル `vectors` を、各 `c.embedding` にも直接セットし、DB セッションへ反映する処理を追加。
  - 検証: チャンク登録後、DB の `chapter_chunks` テーブルの `embedding` カラムに浮動小数点配列が永続化されること。

* **Step 27: 過去チャンク向け Embedding バックフィル（一括生成）ユーティリティの作成**
  - 対象ファイル: `src/services/chunk_ingestion.py`
  - 変更内容: `embedding` が `NULL` である既存チャンクを検出し、バッチで Embedding を計算して保存する `backfill_missing_embeddings(session)` 関数を実装。
  - 検証: 未計算チャンクに対して安全に Embedding が補完されること。

* **Step 28: `GraphRAGService._cosine_similarity` の NumPy / 純Python 最適化**
  - 対象ファイル: `src/services/rag_service.py`
  - 変更内容: 単一のベクトル同士のループ計算から、NumPy（または高速な内積・ノルム一括計算）による行列演算へ最適化。NumPy が利用可能な場合は `np.dot(matrix, query_vec)` による一括コサイン類似度計算に切り替え。
  - 検証: 1000件のベクトル類似度計算が 10ms 以内に完了すること。

* **Step 29: SQLite フォールバック検索の `limit * 3` 打ち切りを撤廃**
  - 対象ファイル: `src/services/rag_service.py`
  - 変更内容: `session.query(ChapterChunk).limit(limit * 3).all()` を撤廃。作品（`book_id`）に紐づく有効なチャンクを適切に全件（または最大1000件等の安全な上限）取得するように修正。
